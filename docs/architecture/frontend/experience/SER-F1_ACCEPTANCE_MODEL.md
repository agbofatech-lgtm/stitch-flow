# Experience acceptance model

No invented percentages. Future stages certify **PASS / CONDITIONAL / FAIL / NOT VERIFIED**.

| Axis | PASS means | FAIL means |
|---|---|---|
| Visual coherence | Shell **and** room interiors use one token world | Frame-only PEX; TailorPro leftovers |
| Cinematic quality | Named category motion on arrival, room, commitment | Spectacle or none where causality needs it |
| Interaction quality | Shared Dialog/Button; keyboard | Per-room modal shells |
| Navigation coherence | Rooms + thread; no nested apps | URL-less confusion **and** lost client thread |
| Workroom quality | Standard slots filled | PageHeader over ErrorState/table |
| Responsive quality | Lab at 320/768/1280/1920 | Unknown (F0 state) |
| Accessibility | Focus, reduce, contrast evidenced | Untrapped overlays |
| Performance | Bundle+runtime measured vs F13 budget | Unmeasured claims of smoothness |
| Data honesty | Local/queued/unavailable visible; no fake sync | Remounted unauth CRUD; “synced” lie |
| Protected integrity | Git-blob hashes unchanged for engines/Studio/types/stages | Any formula/canvas rewrite |

Screenshot lab is **required** for visual/cinematic PASS. F0/F1 have none → those axes cannot be PASSed yet.
